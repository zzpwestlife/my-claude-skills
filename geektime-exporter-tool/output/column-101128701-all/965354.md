你好，我是 Robert。

这是我们第一节实操课，核心目的就是展示 Claude Code 在本章节的真实操作过程，让你对其使用方法有一个更为直观和透彻的了解。

本节实操课将以文字 + 视频的方式进行，主要包含两部分：

- 第一部分是用文稿呈现我自己真实使用 AI Coding 的体验和看法，不是教程，是我自己的落地感受。同时也会回答下课程里大家比较感兴趣的几个问题。
- 第二部分是用录屏呈现顶层设计的完整实操过程，分为四个场景。这部分也会有参考文稿，不过更多细节会在视频里呈现，建议大家优先去观看视频。

## 我的真实体验和看法

目前就我个人而言，离开 Claude Code，我的生产力会严重下降。可能出乎你的意料，我是一个编码量特别大的人，但我跟 Claude Code 的协作，代码只是一部分。

这里总结一下我的哪些工作会交给 Claude Code 完成，具体如下：

- 让它给我做页面。我的开源项目需要运营管理平台，需要官网主页。我不擅长前端，开源社区找前端也非常麻烦。有了 Claude Code 后，这部分全部搞定。而且效果超级好，设计、风格、页面组成我都很满意。
- 让它给我写文档。我的流程一般是，我会跟 Claude Code 讨论某个观点。比如 AI Agent 通信，当前是怎么做的，有什么痛点，业界是怎样的，我会输出我的看法，然后让它给我整理成文章。
- 让它给我做市场调研。因为它有很多信息，比如最近我在研究 AI Agent 之间的通信，我会让它给我讲讲当前实际有什么问题，最新的 AI Infra 公司有在做类似的事情吗，当前的痛点是什么，各自的解决方案是什么。
- 让它给我做角色推演。我针对 AI Agent 通信的痛点出了一个开源方案。然后我让它站在资深基础架构师、一线开发工程师、算法工程师、Agent 自己（OpenClaw）的角度，发表看法。目的是获得各个角色的视角，避免自己技术自嗨，闭门造车。
- 跟它讨论技术方案。我会偶尔跟它讨论技术方案，但频率不高。可能我自己搞开发比较久，很多架构设计的事情我都有自己看法，它最多验证，我不会纯听它的。因为它总是给出看起来对、但是没那么适合我的方案。
- 跟它协作写代码。这是最主要的部分（可能也没那么多）。我自己比较保守，有点代码洁癖，所以我会区分项目的重要程度，确定跟它的合作深度。某些项目让它全部完成，某些项目只让它写部分。
- 让它给我当翻译。我的开源项目的官网英文文档，都是让它生成的，特别快。一句话：帮我生成这份文档的英文版。
- 闲聊。哈哈，这点其实蛮重要的。时不时会有一些 idea，我会快速问它的看法，让它发表观点，效率特别高。

我还用 Claude Code 做了好多事情，如果你感兴趣，我们可以在评论区讨论，或者大家特别有兴趣的话题，我可以在课程中做加餐。

下面我主要展开三个方面。

1. AI 协助做前端页面

我用 AI 协助搭建了开源项目的产品官网。我不是前端工程师，但 AI 让我能独立完成这些工作：帮我快速出页面、跟我探讨产品定位和文案措辞、做竞品和业界方案的调研。AI 在这个场景里的角色是协作者，不是执行者。后面的课程，也会分享哪些地方 AI 帮了大忙，哪些地方它给的东西不能直接用，必须自己判断。

2. 老项目改造

公司内部有一套 SDK 和 Web 项目，跑了很久，代码量大，架构固定。我尝试用 AI Coding 来做改造。老项目意味着既有代码、既有架构、既有约束，AI 不是从白纸开始，而是要在已有的框架里工作。给 AI 做好约束，以小任务执行为主。完整理解项目很难，先让 AI 通过小任务慢慢理解，上下文多了，就会越做越好。后面的课程中，我们也会分享哪些任务 AI 做得好、哪些地方它爱添乱、上下文长度和代码理解力的边界在哪，了解这些也会有帮助。

3. 新项目全部用 AI Coding 写

公司内部一个基于 ZooKeeper 的网关项目，从第一行代码开始就是纯 AI Coding 实现的。不是玩具项目，上线后承接了不小的流量，运行良好，至今没出过问题。这是跟老项目改造完全不同的体验，从零开始，你可以用 SDD 的方式定义规范，让 AI 在你设计的框架里工作。后面的课程中，我会分享新项目全程 AI Coding 的效率、质量、踩过的坑，以及 “人定规范、AI 写代码” 这个协作模式在生产环境的真实验证。

## 总结

两部分内容讲完，顶层设计篇正式结束。

第一部分，不只是几个场景的体验分享，更重要的是让你看到 AI Coding 的使用面远比 “写代码” 宽。做页面、写文档、市场调研、角色推演、技术讨论、翻译、闲聊…… 它是一个全方位的协作者。但它在不同场景下的表现差异很大，关键是你怎么用。

第二部分，四个场景走完，回顾一下你手上现在有什么：

- 一份完整的产品定义（做什么、不做什么、做到什么程度）
- 一套应用架构（模块划分、代码组织规范、外部调用处理）
- 一套系统架构（部署形态、性能瓶颈地图、三阶段扩展路径、数据库规范）
- 一份完整的 CLAUDE.md。

到这，我们没写一行业务代码，但所有决策都已经落成文字。从下一讲开始，Claude Code 就会在这些约束下写代码，它会清楚地知道：模块怎么分、代码放哪里、接口什么格式、索引怎么建、什么不能做。这就是 SDD 的威力，规范定得越清楚，后面写代码越快越稳。
